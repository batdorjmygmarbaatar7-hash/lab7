## Хэсэг E — Дүгнэлт (debrief)

Энэ session-д нийт 8 согог илрүүлснээс аялал тус бүр өөр төрлийн согог өгөв. Couch Potato
(хоосон оролт) аялал хамгийн хурдан үр дүн өгч, валидацийн дутагдлыг (BUG-01) шууд илрүүлэв.
Fed-Ex (өгөгдлийн зам) аялал тоолуурын зөрүү (BUG-02) болон давхардлын асуудлыг (BUG-05)
гаргаж ирэв. Saboteur аялал curl-ээр API руу шууд довтолж, GUI-гаар харагдахгүй гүн согог
болох буруу статус кодыг (BUG-03) илрүүлсэн нь хамгийн гүн олдвор байв. Supermodel (GUI
харагдах байдал) аялал он форматын (BUG-06) болон мессежийн тохироо (BUG-08) алдааг олов.
Хайлтын үсэг ялгах асуудал (BUG-04), /old линкийн 500 алдаа (BUG-07) нь charter-т тусгайлан
төлөвлөгдөөгүй ч навигаци, хайлт турших явцад санамсаргүй илэрсэн.

Charter-аас гадуур хамгийн гэнэтийн олдвор нь "Хуучин хувилбар" линк шууд 500 алдаа өгсөн
явдал байв. Энэ session-д Он-ы хүрээний валидац (1000-2100), сөрөг/хэт том он, маш урт оролт
хүснэгтийг эвдэх эсэх, зохиолчоор тусад нь хайх, байхгүй ID устгах зэргийг шалгаж амжаагүй —
эдгээрийг дараагийн session-ий charter-т оруулна.

Эдгээр согогийн ихэнхийг Лаб 1-ийн Playwright автомат тестээр барих боломжтой: мөрийн
тоо/алдааны мессеж (BUG-01), тоолуур мөрийн тоотой тэнцэх (BUG-02), статус код (BUG-03,
BUG-07), хайлтын үр дүн (BUG-04), давхардлын тоо (BUG-05), мессежийн текст (BUG-08) зэргийг
assert хийж болно. Гэхдээ үүний тулд "юуг шалгах"-аа урьдчилан мэдэж oracle-оо тодорхойлсон
байх ёстой — exploratory тест яг тэрийг нь нээж өгдөг. Он форматын таслал (BUG-06) мэт
харагдах байдлын жижиг согог нь хүний нүдэнд түрүүлж илэрдэг, урьдчилж бодоогүй бол автомат
тестэд ордоггүй. Тиймээс автомат ба exploratory тест бие биеэ нөхдөг.
